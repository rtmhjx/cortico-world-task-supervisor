# Reproducible source build and synthetic tests

Use Node.js 24 or newer and the dependency versions in the root package lock. Install the declared development dependencies in this package. The source tree includes all three adapters and the shared gate; the adapters do not need to be separately installed as Cortico Worlds.

Use the tagged GitHub source checkout for `npm ci`: it includes package-lock.json. Standard npm package tarballs omit package-lock.json, so a downloaded npm tarball is the installable distribution rather than the locked development checkout. Build verification should use the source tag and its lock together.

`node tools/build.mjs` builds the one API 6 World, its independent memory worker and the separate DSH host gateway. `node tools/build.mjs --verify` rebuilds in memory and compares every generated byte, including maps and the prompt. The gateway artifact lives at `vendor/dsh-conversation-gateway/lib/index.js`; install that package inside the real DSH host. It cannot run inside Cortico as a substitute for DSH's native lifecycle APIs.

For SDK typechecking and real EventStore integration tests, set `CORTICO_DIR` to a compatible Cortico source checkout. `CORTICO_SOURCE_ROOT` and `CORTICO_SOURCE` are accepted aliases. The package uses the SDK's source types and real EventStore without copying its source or changing its files. Run `node tools/typecheck-vendor.mjs --all` and `node tools/test-vendor.mjs` after building. The test runner includes root and vendor `.test.ts`/`.test.mjs` tests and accepts optional name substrings to select a subset.

If development dependencies are already installed in a separate checkout, `CORTICO_TOOLCHAIN_ROOT` can point to that checkout instead of installing a second copy. This is optional; the default is this package's own development dependencies. No source file assumes a global drive, username or external node_modules path.

The optional `DSH_SOURCE_ROOT` points to an existing DSH source installation with compiled `@deepseek-ai` packages. It enables seven prepared-session acceptance cases against the actual native SessionQueryEngine. Those tests provide only synthetic in-memory persistence and forbid all native writes, prompts, cancellation and live-agent resolution. Without this explicit prerequisite they are reported as skipped. Desktop named-pipe protocol tests are Windows-specific. All other fixture state is written to newly created operating-system temporary directories, never an existing DSH/Codex/Cortico profile.

The built-worker test executes the published `.mjs` worker with no TypeScript loader, so a source-only worker omission fails the test. The old workbench audit CLI and production monitoring scripts are deliberately excluded; no test reads deployment credentials, actual chat history or local runtime reports.

The setup form's excluded directories must be copied into the separate gateway plugin's `excludedRoots` array. The gateway binds that policy to its own bundle and includes it in persisted identity, native authorization and health; changing it requires a native-host restart and state review. `CORTICO_TASK_SUPERVISOR_EXCLUSIONS` is an optional administrator policy shared by both processes, rather than a setup prerequisite. The public default protects `~/.task-supervisor/private`; source-specific workspace exclusions remain available. Do not copy a private deployment's paths or credentials into the example configuration or release manifest.
